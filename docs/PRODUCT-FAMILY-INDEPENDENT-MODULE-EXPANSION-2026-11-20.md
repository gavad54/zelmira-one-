# نقشه جامع توسعه خانواده مستقل محصولات VAYRO
تاریخ: 2026-11-20  
وضعیت: طراحی اجرایی و قرارداد دامنه؛ **پیاده‌سازی/استقرار محسوب نمی‌شود**

## 1) تصمیم معماری قطعی

- VAYRO تنها اپ مادر، مالک محصول و لایه مدیریت پرتفوی، هویت مالک، قراردادهای بین‌محصولی و گزارش تجمیعی است.
- DANA مرکز فرماندهی و هوش مصنوعی مشترک است؛ پیشنهاد، پایش، تحلیل و اجرای مجاز را با ثبت رویداد و تأیید انسانی برای اقدامات حساس انجام می‌دهد.
- یازده محصول زیر مستقل‌اند: ARVAND، CHARSU، GANJINEH، NEGAH، SEPEHR، NAMA، PAYAM، LEADORA، ARIANA، ARIA و ARMIN MARKET.
- استقلال یعنی هر محصول مالک دامنه، شناسه‌ها، API، داده، مجوزها، رابط کاربری، نسخه‌بندی، چرخه انتشار، بودجه و صورت درآمد مستقل خود را دارد. استفاده از سرویس مشترک فقط از API نسخه‌دار و قرارداد روشن مجاز است؛ DB مشترک یا دور زدن کنترل دسترسی ممنوع.
- ساختار قدیمی و همه قابلیت‌های معتبر، شناسه‌ها، قراردادها، آرشیوها و تصمیم‌های قبلی حفظ می‌شوند. توسعه جدید additive است. حذف/ادغام/تغییر شناسه فقط پس از inventory، crosswalk، آزمون رگرسیون، backup/restore و تأیید مالک مجاز است.
- ARIA بدون حسابداری، ERP، دفترکل و امور مالی شرکتی باقی می‌ماند. همه این دامنه‌ها فقط در ARIANA هستند. LEADORA و ARVAND می‌توانند اطلاعات عملیاتی و محاسبات مدیریتی داشته باشند، اما دفترکل مرجع ایجاد نمی‌کنند.

## 2) معماری استاندارد مستقل هر محصول

هر محصول به‌صورت modular monolith مرزبندی‌شده آغاز می‌شود؛ جداسازی سرویس فقط با شواهد بار/امنیت/مالکیت داده انجام می‌شود.

1. Experience: اپ موبایل/وب، navigation، فرم‌ها، جست‌وجو، RTL/LTR، accessibility و حالت‌های loading/empty/error/offline.
2. Identity & Access: عضویت، نقش‌ها، مجوز سطح منبع و عملیات، MFA در عملیات حساس، نشست و بازیابی حساب.
3. Domain Core: مدل‌های دامنه، قواعد، وضعیت‌ها، invariantها و workflowها؛ منطق کسب‌وکار در UI قرار نمی‌گیرد.
4. API: قرارداد OpenAPI نسخه‌دار، اعتبارسنجی ورودی، pagination، idempotency، rate limit و خطاهای قابل اقدام.
5. Persistence: پایگاه داده اختصاصی محصول، migration نسخه‌دار، قیدهای یکتا/ارجاعی، tenant isolation و retention.
6. Async Work: صف کار، scheduler، retry/backoff، dead-letter، deduplication و مشاهده‌پذیری.
7. Integrations: آداپتورهای رسمی با timeout، circuit breaker، consent، source provenance و وضعیت اتصال؛ آداپتور خالی یا mock اتصال زنده محسوب نمی‌شود.
8. Audit & Security: ثبت رویداد غیرقابل‌انکار، رمزنگاری، مدیریت secrets، کنترل فایل، threat model و dependency scanning.
9. Analytics: KPI با فرمول، منبع، timestamp و drill-down؛ تفکیک درآمد وصول‌شده، درآمد تعهدشده، GMV و pipeline.
10. Commercial: طرح رایگان/آزمایشی/پولی، محدودیت مصرف، صورتحساب، مجوز، تمدید، لغو، refund و پشتیبانی؛ فعال‌سازی پرداخت فقط پس از تست و مجوز.
11. Operations: health/readiness، logs/metrics/traces، backup خارج از میزبان، restore drill، runbook، rollback و release evidence.

## 4) VAYRO و DANA — لایه مادر و هماهنگ‌کننده، نه محصول جایگزین

### VAYRO
- ثبت و مالکیت پرتفوی 11 محصول
- مدیریت اشتراک و مجوز در سطح قراردادهای بین‌محصولی
- داشبورد تجمیعی درآمد/هزینه/وضعیت؛ داده هر محصول از API مجاز
- مدیریت مالک و سیاست‌های مشترک
- کاتالوگ محصولات و onboarding
- billing orchestration بدون نگهداری غیرمجاز وجوه
- قراردادهای API و نسخه‌بندی
- وضعیت release، incident و ریسک هر محصول
- پشتیبانی و درخواست‌های بین‌محصولی
- گزارش عملکرد کلان با تفکیک واحدهای مالی

### DANA
- ارکستراسیون agentها و وظایف با policy و scope
- تحلیل KPI و کشف ناهنجاری با ارجاع به منبع
- تولید پیشنهاد بهبود محصول و اولویت‌بندی
- مهندسی و تحلیل خطا با تأیید تغییر
- پایش امنیت و وابستگی‌ها

- کنترل هزینه منابع و هشدار بودجه
- گزارش روزانه قابل استناد
- تأیید انسانی برای پرداخت، حذف داده، تغییر دسترسی، انتشار و تعهد حقوقی

DANA نباید به‌صورت خودکار به حساب‌های کاربران، secrets یا داده خصوصی محصولات دسترسی نامحدود داشته باشد. هر دسترسی محدود، ثبت‌شده، قابل لغو و متناسب با وظیفه است.

## 6) استاندارد تبدیل «ایده/آداپتور» به قابلیت عملیاتی

هر قابلیت باید این پرونده را کامل کند:
1. Requirement ID و محصول مالک
2. مسئله مشتری و نقش استفاده‌کننده

وضعیت‌های استاندارد: INVENTORIED، DESIGNED، IMPLEMENTED، TESTED، INTEGRATED، STAGING_VERIFIED، PRODUCTION_VERIFIED، MONETIZATION_VERIFIED. «enabled»، «adapter exists»، «screen exists» یا «test passed» به‌تنهایی وضعیت عملیاتی/درآمدی نیست.

## 7) مدل درآمد و کنترل کیفیت تجاری

- درآمد هر محصول در ledger تحلیلی خودش ثبت می‌شود؛ VAYRO فقط aggregation مجاز انجام می‌دهد.
- انواع درآمد: subscription، usage/metering، transaction commission، professional tools، managed services، API/data services، advertising با برچسب.
- درآمد وصول‌شده، درآمد تعهدشده، GMV، ارزش pipeline و پیش‌بینی جداگانه‌اند.
- هر خدمت پولی باید تعرفه، واحد مصرف، محدودیت، شرایط لغو/refund، پشتیبانی، مالیات/صورتحساب و رویداد ثبت درآمد داشته باشد.
- هیچ درآمدی از فروش داده شخصی، پیام ناخواسته، نشان اعتبار غیرواقعی، رتبه‌بندی پنهان یا وعده نتیجه تضمینی طراحی نمی‌شود.
- رشد درآمد با افزایش ارزش واقعی و حفظ مشتری، نه با ساخت ماژول‌های بی‌مصرف، سنجیده می‌شود.

## 9) اولویت مسیرهای end-to-end برای اثبات محصول واقعی

- ARVAND: شرکت → کالا → RFQ → پیشنهاد → معامله → سند → حمل → تحویل → landed cost.
- CHARSU: فروشنده → کالا → جست‌وجو → سبد → سفارش → ارسال → تحویل → مرجوعی/بازپرداخت.
- GANJINEH: ایجاد فروشگاه → دامنه → محصول → انتشار → سفارش → fulfillment → گزارش فروش.
- NEGAH: بریف → برآورد → پروژه → تولید → تأیید → تحویل → صورتحساب خدمت.
- SEPEHR: workspace → provision → deploy → monitoring → backup → restore → metered invoice.
- NAMA: ایجاد سایت → ویرایش → preview → SEO check → انتشار → تحلیل → تمدید اشتراک.
- PAYAM: رضایت مخاطب → segment → کمپین → ارسال مجاز → conversion tracking → ROI.
- LEADORA: مشتری → SKU → سفارش → رزرو موجودی → pick/pack → توزیع → proof-of-delivery → خروجی مالی.
- ARIANA: سند منبع → ثبت دوطرفه → کنترل توازن → گزارش → بستن دوره → اصلاحیه قابل ممیزی.
- ARIA: پروفایل → کشف خدمت → درخواست → تطبیق → گفتگو → انجام خدمت → بازخورد/گزارش.
- ARMIN MARKET: ثبت نیاز → فروشندگان مرتبط → پیشنهاد → مقایسه → انتخاب → پیگیری نتیجه.

## 10) وضعیت و ممنوعیت ادعا

این سند فقط قرارداد معماری و دامنه توسعه را تثبیت می‌کند. تا زمانی که کد، DB، API، آزمون و محیط واقعی هر مسیر بررسی نشده، هیچ ماژولی IMPLEMENTED یا PRODUCTION_VERIFIED اعلام نمی‌شود.
